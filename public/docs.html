Ayaka Sync API

Ayaka Sync API issues and manages REST API keys, enforces per-key permissions and rate limits, and records every request for analytics. All endpoints live under a single versioned base URL and return JSON.

Base URL
https://your-domain/api/v1

Every response uses the same envelope:

json · success
{
  "success": true,
  "message": "Request successful",
  "data": {},
  "meta": { "timestamp": "2026-01-01T00:00:00Z" }
}
Open API Reference openapi.json

Authentication

Developer endpoints authenticate with an API key. Send it in the Authorization header using the Bearer scheme. The X-API-Key header is also accepted.

http
Authorization: Bearer ayk_live_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
# or
X-API-Key: ayk_live_XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX
  • Keys are only accepted over headers — never put them in URLs or query strings.
  • Call the API from your server. Don't ship production keys in browser or mobile bundles.
  • The dashboard itself uses HttpOnly session cookies with CSRF protection; dashboard-only endpoints reject API keys.

API Keys

Create keys in Dashboard → API Keys. The full key is displayed once; only its HMAC-SHA256 hash is stored.

adminEverything above plus GET /keys, GET /keys/{id}, POST /keys/{id}/revoke. Requires your password to grant.

Optionally restrict a key to specific paths with allowed endpoints, e.g. /api/v1/records/*. Keys can also have an expiration date, a custom rate limit, and can be disabled, regenerated or revoked at any time.

Usage

          
Every request authenticated with an API key — successful or not — is recorded with its request ID, endpoint, method, status code, response time, key, IP and user agent. Authorization headers, full keys, passwords and request bodies are never logged.

          
Usage powers the Overview and Analytics pages. If the usage write fails, your request still succeeds; the event is retried in the background and the failure counter is exposed at GET /health.

          
Each response carries an X-Request-ID header you can search for in Recent API Activity.

        


        

          
Rate Limits

          
Each key has its own limit (default 60 requests per minute, configurable per key from 1 to 10,000). Counters are stored in PostgreSQL, so limits hold across serverless instances.

          

            
HeaderMeaning

            
              
X-RateLimit-LimitRequests allowed in the current window

              
X-RateLimit-RemainingRequests left in the window

              
X-RateLimit-ResetUnix timestamp when the window resets

              
Retry-AfterSeconds to wait (only on 429)

            

          
json · 429
{
  "success": false,
  "message": "Rate limit of 60 requests per minute exceeded",
  "error": { "code": "RATE_LIMIT_EXCEEDED" },
  "meta": { "timestamp": "2026-01-01T00:00:00Z", "request_id": "req_…" }
}

          
Sign-in is separately protected: repeated failed logins for an account or network are blocked for 15 minutes.

        


        

          
Errors

          
Errors use the envelope {"success": false, "message", "error": {"code", "details?"}, "meta"}. Branch on error.code, not on the message.

Examples

          
Store your key in an environment variable (AYAKA_API_KEY) — never hard-code it.

          
Verify a key

          

            


curl https://your-domain/api/v1/example \
  -H "Authorization: Bearer $AYAKA_API_KEY"


import os
import requests

BASE_URL = "https://your-domain/api/v1"
headers = {"Authorization": f"Bearer {os.environ['AYAKA_API_KEY']}"}

resp = requests.get(f"{BASE_URL}/example", headers=headers, timeout=10)
body = resp.json()
if not body["success"]:
    raise RuntimeError(f"{body['error']['code']}: {body['message']}")
print(body["data"]["key"])


const BASE_URL = "https://your-domain/api/v1";

const res = await fetch(`${BASE_URL}/example`, {
  headers: { Authorization: `Bearer ${process.env.AYAKA_API_KEY}` },
});
const body = await res.json();
if (!body.success) throw new Error(`${body.error.code}: ${body.message}`);
console.log(body.data.key, res.headers.get("X-RateLimit-Remaining"));

          


          
Create and list records

          

            


curl -X POST https://your-domain/api/v1/records \
  -H "Authorization: Bearer $AYAKA_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"collection": "orders", "data": {"id": 1001, "total": 49.9}}'

curl "https://your-domain/api/v1/records?collection=orders" \
  -H "Authorization: Bearer $AYAKA_API_KEY"


import os
import requests

BASE_URL = "https://your-domain/api/v1"
s = requests.Session()
s.headers["Authorization"] = f"Bearer {os.environ['AYAKA_API_KEY']}"

created = s.post(f"{BASE_URL}/records", json={"collection": "orders", "data": {"id": 1001, "total": 49.9}}, timeout=10)
created.raise_for_status()

page = s.get(f"{BASE_URL}/records", params={"collection": "orders"}, timeout=10).json()
for record in page["data"]:
    print(record["id"], record["data"])


const BASE_URL = "https://your-domain/api/v1";
const headers = {
  Authorization: `Bearer ${process.env.AYAKA_API_KEY}`,
  "Content-Type": "application/json",
};

await fetch(`${BASE_URL}/records`, {
  method: "POST",
  headers,
  body: JSON.stringify({ collection: "orders", data: { id: 1001, total: 49.9 } }),
});

const list = await (await fetch(`${BASE_URL}/records?collection=orders`, { headers })).json();
console.log(list.data, list.meta.total);

          


          
Handle rate limits

          
python
import time, requests

def call(url, headers, attempts=3):
    for _ in range(attempts):
        r = requests.get(url, headers=headers, timeout=10)
        if r.status_code != 429:
            return r
        time.sleep(int(r.headers.get("Retry-After", "1")))
    return r
